# SQLite for the control plane

Date: 2026-11-07. Status: accepted, implemented by issue #15. Supersedes the database part of
[two deployables](2026-11-07-two-deployables.md) and of the platform research (§4).

## Context

The control plane is one process serving one owner. The plan had PostgreSQL because the references built for many
tenants use it; the orchestration core needs guarded transitions, one writer at a time, leases, an event log and an
outbox, not many writer processes. On the control plane host the coordinator has a shell as another OS user, so a
database reachable over localhost TCP is one more service to authenticate, while a file can simply be unreadable.

## Decision

- The control plane keeps its state in one SQLite file through `internal/shared/sqlite`, as Orca keeps its
  orchestration database (`src/main/runtime/orchestration/db/orchestration-db.ts`: WAL, `busy_timeout`, every
  lifecycle write `BEGIN IMMEDIATE` with a guarded `UPDATE`) and as Omnara opens its node state database
  (`internal/machinedaemon/statedb/store.go`).
- `modernc.org/sqlite` (pure Go, no cgo); one connection; `_txlock=immediate`; pragmas `journal_mode=WAL`,
  `synchronous=FULL`, `busy_timeout=5000`, `foreign_keys=ON`, `trusted_schema=OFF`, `temp_store=MEMORY`, read back
  after opening; an absolute path; the directory 0700 and the file 0600; an existing file others can read is refused.
- The node's state database uses the same package.
- Tests open a real file in a temporary directory; no containers.

## Alternatives considered

- **PostgreSQL** (Omnara, MemoryOS, second-bite): needed for several writer processes, several control plane
  instances or many users. It costs a server, credentials on localhost, and backups with `pg_dump`. None of its
  extras (`FOR UPDATE SKIP LOCKED`, `LISTEN`/`NOTIFY`) is needed with one writer process.
- **SQLite with a connection pool**: more read concurrency, but writers then contend for the lock; one connection is
  simpler and correct, and a separate read-only pool can be added if measurements ask for it.
- **`synchronous=NORMAL`** (Orca): faster commits, but a power loss can drop the last transactions; orchestration state
  is worth the slower commit (Omnara uses `FULL`).

## Consequences

- Claiming needs no row locks: one connection serializes writes.
- River's SQLite driver (`riversqlite`, v0.51.1) is supported but younger than its PostgreSQL driver, with many
  recent SQLite fixes in its changelog; whether to use it or an outbox table of our own is decided in the orchestration
  core's design.
- Backups copy the file (`VACUUM INTO`) or stream it with Litestream, set up with the deployment.
- Moving to PostgreSQL is a migration of the queries kept in sqlc, done when a reason above appears.
