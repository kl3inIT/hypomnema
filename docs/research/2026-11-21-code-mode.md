# Code mode: tools called from code, for workers and Bots

Date: 2026-11-21. Asked by the owner for [issue #1015](https://github.com/kl3inIT/hypomnema/issues/1015): code
mode is said to cut tokens a lot; how do the references support it, how does the community rate it, and should
Hypomnema's workers and Bots prefer it. Research only; no code.

**Code mode**: the model gets one tool (`exec`, `execute`, `codemode`) and writes a short program that calls the
other tools as functions, so intermediate results stay out of the context. **Tool search** (deferred tools) is a
different thing: definitions load on demand, but each tool is still called one by one. Much of the saving reported
for code mode comes from the second.

Clones read under `.tmp/` (2026-11-21): pi `827383a15` and the published `pi-coding-agent` 1.5.2, codex
`345f166d`, opencode `6205e99c`, openclaw `7ff0d902b`, hermes-agent `e93b3da9a8`, openmausbot `c175749a8`,
omnigent `2641a4a`, bifrost `03ead19`, kilocode `46e4dd4`; omp, oh-my-opencode, librechat, litellm, omnara, t3code,
cline, gemini-cli, openhands and aider searched. Rows a helper searched and that were not re-read line by line are
marked (H).

No code mode in omp (its `eval` cell can call `tool.<name>()`, not its purpose), oh-my-opencode (an external engine),
librechat (off), litellm, omnara, t3code, cline, gemini-cli, openhands, aider (H).

Common ground: **tool search for MCP is the majority default**. Code mode is split: on for MCP in pi, opencode
and Codex's models, per model in OpenClaw, off or opt-in in kilocode, bifrost, librechat, Onyx; Omnigent turns opencode's
off for approvals. None gives the code files or network directly: the outside is reached only through tools. Inner
calls keep the normal permission checks (pi, OpenClaw, kilocode, Hermes); outputs are capped (pi and Codex 10k
tokens, Hermes 50 KB); pi keeps the tool description fixed while servers connect, to keep the prompt cache
(`tool.js:119-124`).

## 2. Primary sources and measurements

| Source | Measured | Claimed |
|---|---|---|
| [Cloudflare, Code Mode](https://blog.cloudflare.com/code-mode/) (2025-09-26) | — | Models write TypeScript better than synthetic tool calls; V8 isolate with only MCP bindings |
| [Cloudflare, an API in 1,000 tokens](https://blog.cloudflare.com/code-mode-mcp/) (2026-02-20) | ~1,000 vs 1.17M definition tokens for 2,500 endpoints (tiktoken) | Generated code hardcodes response shapes; client side needs a sandbox |
| [Anthropic, Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp) (2025-11-04) | — | One example, 150,000 → 2,000 tokens; names the sandbox's operational cost; no code released |

| [Programmatic tool calling docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling) | — | `allowed_callers` "is not a hard API-level block"; not with MCP connector tools, `strict`, forced `tool_choice` |
| [Goose](https://dev.to/goose_oss/8-things-you-didnt-know-about-code-mode-4h71) | 23,339 vs 33,648 tokens (−30 %), one task run twice | Skip for one tool or one or two extensions |
| [CodeAct](https://arxiv.org/abs/2402.01030) (ICML 2024) | gpt-4: 74.4 % with code vs 52.4 % JSON, 5.5 vs 7.6 turns; best for 12 of 17 models; open models near zero | — |
| [The Bitter Lesson of Tool Calling](https://arxiv.org/abs/2608.06370) (2026-08-06), BFCL v4, 14 models | Code ≥ JSON for 11 of 14 (Sonnet 4.6 +6.5); collapses for GPT-4o −26.9, GPT-5.4-mini −24.3, GPT-4.1 −19.8 (escaping); **more tokens below ~26 calls**, 1.5× input on chaining; latency about halved | Echo stubs, small ablations |
| bifrost docs | −58 % input tokens at 96 tools, −92.8 % at 508 | Vendor's own benchmark |

Community ([HN on Cloudflare](https://news.ycombinator.com/item?id=45399204),
[HN on advanced tool use](https://news.ycombinator.com/item?id=46038047),
[HN on pi's codemode](https://news.ycombinator.com/item?id=49978333),
[Ronacher](https://lucumr.pocoo.org/2026/10/6/codemode/),
[Willison](https://simonwillison.net/2025/Nov/4/code-execution-with-mcp/)):

- The large figures (98–99.9 %) count definition tokens or one chosen example; per task the measured saving is
  30–37 %, and on short tasks code mode can cost more.
- It pays off with a strong model, many tools or large definitions, chains of three or more dependent calls, wide
  fan-out, and large outputs filtered in code.
- Against: weaker or smaller models write broken code (both papers; Codex warns when a model does not advertise
  support); overkill for a small tool set; a sandbox to run; one `execute` hides many actions from approval;
  errors inside a block are harder to place. No source measures the effect on prompt caching.

## 3. Hypomnema today (read on `main`, 2026-11-21)

| Agent | Code mode | Read where |
|---|---|---|
| pi (coordinator, chat Bots) | Off: the `hypomnema` server has `direct` exposure (owner, 2026-11-15) | `internal/controlplane/clientcli/mcp.go:101-110` |
| opencode workers | Off on purpose: `execute` is denied so the tools server's tools are plain tools | `internal/node/acp/agents.go:98-118` |
| omp workers | Nothing set; omp has no code mode | `internal/node/acp/agents.go:67-95` |
| Claude Code workers | None exists; tool search is Claude Code's default, not set by the node | `internal/node/claude/runner.go:101,240-250` |
| Codex workers | **On, code-mode-only**, by Codex's own catalog: the gateway serves Codex's bundled entries with their fields (`codex_catalog.go:18-27`), and 13 of 14 say `"tool_mode": "code_mode_only"`; nothing in the node overrides it | `internal/controlplane/modelgateway/codexmodels/models.json:20`; `internal/node/codex/runner.go:80-99` |

So Hypomnema is mixed without having chosen to be: Codex workers already run code mode, as stock Codex does;
opencode's is switched off; pi's is off by the owner's choice. Not checked on a node: that `codex-code-mode-host`
is installed (without it, only-mode refuses to run; Codex workers do run, so inferred present), and how many
tokens a Codex worker's Task takes against another worker's on the same work.

## 4. Recommendation

Keep the default most references share: **direct tools plus tool search for workers and Bots, and leave each
worker's own code mode where its maker defaults it** (Codex on, as its catalog says). Do not turn on code mode for
pi or opencode now.

- From: tool search is the majority default (pi, Codex, OpenClaw, Hermes, Claude Code, OpenMausBot, Omnigent);
  Omnigent turns opencode's code mode off for per-tool approval, as Hypomnema does.
- Why not more: the `hypomnema` server is one server with a few dozen tools, below the point where measurements
  show a gain (more than about 10K tokens of definitions, or ~26 calls in a task); Bots run several non-frontier
  models through the gateway, where both papers show code mode breaking; and per-tool approval and the transcript
  per tool call would be lost.
- Measure before changing: each Task's usage (`TaskUsage`, `hypomnema tasks show` "used:", ARCHITECTURE.md;
  issue #856) already records its tokens. Compare Codex
  Tasks (code mode) with Claude Code and opencode Tasks of the same kind over a week; if Codex's tokens per Task are
  clearly lower, revisit opencode's `execute` and pi's `codemode` exposure for the `hypomnema` server.
