Common ground: the node dials out with a bearer token and holds one WebSocket, liveness is checked at the application
level with a short reconnect backoff (Omnara caps it at 30 s, Coder at 10 s, Omnigent at 3 s), and output is resent
until it is acknowledged.

Liveness in Omnara:
- heartbeat every 10 s, set by the server; presence TTL 3 × the heartbeat;
- WebSocket ping every 20 s with a 10 s timeout; read timeout 70 s;
- backoff from 1 s to 30 s with jitter; 401 or 403 stops the daemon.

## What Hypomnema takes

The design is in issue #32:
- **The link:** Omnara's, the closest reference (Go, one daemon per machine): HTTP hello with claims and
  dispositions, then one WebSocket with JSON envelopes, offers accepted by a report, reports acknowledged and resent
  from a local outbox. Our report id is the orchestration core's request id, so its receipts make a resend harmless.
- **The worker:** a shim per worker as Omnara's runner (`setsid`, its own journal; spike 1b), `KillMode=process`,
  and stale groups killed before a restart (durable-harness).
- **The working copy:** `git worktree` as Orca and Omnigent.
- **Talk-back:** an MCP server through `--mcp-config` (Omnigent) with `ask` and `finish`. `finish` is called once
  (Orca's `worker_done`); a stop without it is a failure (Orca).
- **Credentials:** one `CLAUDE_CONFIG_DIR` per account (Orca) on a clean environment (durable-harness).

An earlier draft proposed HTTP long-polling instead of the WebSocket. No reference does that, and the owner rejected
it.
