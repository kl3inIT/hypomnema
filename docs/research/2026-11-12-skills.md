# Skills held by the control plane

Date: 2026-11-12. Asked by the owner as the next piece of issue #21 (shared infrastructure): how the references keep
skills, bring them to the machine an agent runs on, and make each CLI see them; and what else such a control plane
keeps besides skills.

Read in the clones under `.tmp/` by three sub-agents, with the points the design rests on read again directly:
Omnara, Coder, OpenClaw, Hermes, OpenMausBot, Omnigent, OpenHands (app and SDK), Orca, and the skill discovery of
Codex, pi, omp and opencode.

## 1. The format is shared; managing skills is not

Every reference and every CLI reads the Agent Skills format (agentskills.io): a folder with a `SKILL.md` whose
frontmatter has `name` and `description`, plus scripts and references. pi links the standard in its loader
(`pi/packages/coding-agent/src/core/skills.ts:350`). Coder's stored skills are one markdown file without supporting
files (`coder/coderd/x/skills/doc.go`). The standard says nothing about storage, versions, delivery or who may use
a skill; each reference does that its own way.

Where each CLI looks by itself:

| CLI | Folders | Source |
|---|---|---|
| Claude Code | `.claude/skills`, `~/.claude/skills`, a plugin's `skills/` given by `--plugin-dir` | Omnigent `omnigent/inner/bundle_skills.py` |
| Codex | `.agents/skills` up the repository, `$CODEX_HOME/skills` | `codex/codex-rs/skills/src/lib.rs`, Omnigent `inner/codex_staging.py` |
| pi | `~/.pi/agent/skills`, `.pi/skills`, `.agents/skills` up the repository | `pi/.../core/skills.ts:458-463`, `package-manager.ts:514` |
| omp | `.agent/skills`, `.agents/skills` (project walk-up and home) | `omp/packages/coding-agent/src/discovery/agents.ts:159-177` |
| opencode | `skill/`, `skills/` under each config directory; `.claude/skills`, `.agents/skills` | `opencode/packages/core/src/config/plugin/compatibility.ts:45` |

| OpenClaw | Files in tiers; a library of immutable revisions whose hash covers paths, content, sizes and executable flags; identical saves are no-ops (`docs/tools/skills.md` "Revisions and session selection") | Watcher and rescan; nodes publish their own | Claude CLI through a temporary `--plugin-dir`; Codex's own skill paths turned off | Per agent allowlist, workspace, global. ## 3. What they agree on

- A skill is kept whole (the folder, not only `SKILL.md`) and identified by a digest of its files: Omnara, OpenClaw,
  Orca, Omnigent, OpenMausBot. Five of eight keep revisions or a lock with a hash.
- Which skills an agent gets is decided per agent, bot or profile: OpenClaw, OpenMausBot, Omnara, Omnigent, Hermes.
- The CLI finds the skills by itself in a folder of its own; where a session must see only its skills, that folder
  is made for the session (Omnigent for Claude and Codex, OpenClaw for Claude).
- Installing from a GitHub repository at a ref: Omnigent, OpenHands, OpenClaw, Hermes, OpenMausBot.
- Skills shipped with the product are kept apart from the ones a person adds: Orca, Hermes, OpenMausBot.

## 4. Besides skills

What the same references keep for their agents, and where Hypomnema stands (2026-11-12):

| Kind | References | Hypomnema |
|---|---|---|

| Files the owner gives an agent | Omnigent: the original kept by the server, the machine's copy a cache (`omnigent/entities/file.py`); Omnara through artifacts | None |
| MCP servers | Omnigent registry and gateway, Coder `mcp_server_configs`, Omnara catalogs, OpenMausBot, OpenHands | The service proxy covers the services so far |
| Memory | All but Omnigent and Orca | Bots' memory (issue #169) |
| Schedules | All eight | Issue #211 |
| Machine setup, templates | Coder templates, Omnara pools | Setup script and tool catalog (issue #186) |
