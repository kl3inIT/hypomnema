# Glossary

One meaning per term. Use these words in code, documents, issues and messages. A term from a reference project that
means something else is named here once and not used.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Owner** | The one person who assigns work, approves gates and owns every resource | A user of a multi-tenant product |
| **Run** | One objective from the owner, such as "add login with Google to second-bite". Holds Tasks | A model "run" or a CI run |
| **Task** | One unit of work inside a Run, with dependencies on other Tasks of the same Run (a DAG) | Orca's task, which has the same meaning |
| **Dispatch** | One attempt to carry out a Task: placed on one Node with one Runtime, with an epoch for fencing. A retry is a new Dispatch | The Task itself; a Task may have many Dispatches |
| **Gate** | A decision a Task waits on, answered by the owner (plan approval, merge approval, a question) | A per-tool-call permission prompt, which is a Policy verdict |
| **Coordinator** | The agent that plans a Run, creates its Tasks, answers or forwards its workers' questions and summarises results; it does not do the work itself, and the control plane holds the Run's state. It is a part in a Run: a Bot takes it, or the owner's own agent (Claude Code, Codex) calling the Client API; each Run has one, recorded by its token. Until 2026-11-11 the glossary said "it is pi on the server" and that it holds no state; a Bot has a memory. Called Brain until 2026-11-07, as in older research notes; the role is Orca's coordinator | A worker |
| **Setup change** | A change of a Bot or a worker Profile that the Bot `coordinator` made from a chat: made, changed or removed, applied at once, shown as a card in that chat with Undo while nothing changed or used it since. After OpenMausBot's team setup receipt (issue #169) | A Routine's change by a Bot, which the Routine itself records |
| **Bot** | A long-lived agent of the control plane: a name, a model, a persona the owner writes and a memory it keeps across chats. It talks with people in Chats, on the web or through a Channel, gives work to workers and may do work itself. It runs pi on the server. The first one, `coordinator`, was the Profile `coordinator` until 2026-11-11. The word is OpenMausBot's (owner, 2026-11-11) | A Worker, which carries out one Dispatch on a node and ends; a Profile, which is a worker's recipe; a Channel, which Lark calls a bot |
| **Routine** | Work a Bot does on a schedule, every N minutes or by a cron expression with its time zone: a prompt the Bot works on with its model in a new Chat each run, or a script, a file in the Bot's directory, that runs with the Bot's tools and no model. The owner makes one, or a Bot does from its chat; it is on at once, and a Bot's change can be undone. Each run leaves a record. The word is OpenMausBot's (issue #211) | A Run, which is one objective from the owner and holds Tasks; a Task; a connector that syncs data, which is not built |
| **Channel** | A door to a Bot from a messaging service: a Lark app and who may talk through it. A person's message there is a message of a Chat with the Bot | The Bot behind it; an Integration, through which agents use a service |
| **Chat** | A conversation with a Bot, kept by the control plane; a Run the Bot creates belongs to its chat, which its events wake | pi's own session file, which pi resumes from, not the record; the Bot's memory, which is the same in all its chats |
| **Orchestration** | The control plane module that keeps Runs, Tasks, Dispatches, Gates, leases, mailboxes and the event log, and is the only writer of that state. It runs nothing itself. Called execution until 2026-11-07; the name is Orca's (`src/main/runtime/orchestration/`) | The Coordinator, which decides; orchestration keeps the record |
| **Worker** | A CLI agent process (Claude Code, Codex, omp, opencode) carrying out one Dispatch | The Node it runs on; a Bot, which runs on the server and lives on |
| **Conversation** | A Worker's CLI conversation (a Claude Code session id, a Codex thread id) on one Node and worktree, recorded by orchestration. A later Dispatch of the same Task continues it when the previous Dispatch settled cleanly; a crash or an unknown outcome starts a new one with a recovery note | A Dispatch, which is one attempt and ends; a vault Session |
| **Runtime** | The kind of worker and how it is driven: `claude`, `codex`, `omp`, `opencode` | A model or a provider; pi, which a Bot runs on the server |
| **Skill** | A folder in the Agent Skills format (a `SKILL.md` with a name and a description, and files beside it) that an agent's CLI reads by itself when its work needs it. The owner adds one to the control plane, which keeps it in versions known by a digest of their files (called revisions in the API, the CLI and the code, whose names stay; the web says version, as for a Profile and a Secret: owner, 2026-11-12); a built-in skill ships compiled into the binaries | A tool, which an agent calls; a Profile's instruction, which is always in the prompt |
| **Profile** | A named, versioned choice of runtime, provider, model, effort and instruction that a worker runs with, through its Task. pi on the server ran as the Profile `coordinator` until 2026-11-11 and is a Bot since. A change is a new version; a Dispatch records the version it ran with. Called Role until 2026-11-09, when roles were defaults read from the environment | A Runtime, which is code on the node; the owner's own agent, whose model the owner picks |
| **Memory** | Entries, one per line, that an agent keeps across its work: a Bot's across its chats, an agent's (a Profile's) across the Tasks of all its workers, and the memory about the owner that every worker and Bot gets. Kept by the control plane (owner, 2026-11-13: MemoryOS until then) | A Transcript, which is what one Worker said and did; a machine's memory (RAM) on the Machines page; a CLI's own memory, which is off for workers |
| **Node** | A machine paired with the control plane that runs Workers: a VM, a server, a sandbox | Omnara's "machine", same meaning |
| **Account** | One credential for a model provider: a Claude, Codex or Antigravity subscription, or an API key. Kept by the control plane; a Runtime runs under it directly, the Model gateway serves it, or both; a Dispatch records which one it used | A user account of the owner |
| **Client API** | The control plane's one API, `/api/v1`, described by `api/openapi.yaml`, which the web client calls with a Web session, and the `hypomnema` CLI and coordinators with a Client token | The node API (nodes only); the Model gateway |
| **Client token** | A bearer token for the Client API, of kind `owner` (everything) or `coordinator` (its own Runs, and reading the rest); shown once, stored as a hash. A `bot` token is one pi process's own: what its coordinator token does, in its chat and as its Bot only, made when that pi starts and ended with it (issue #260) | A node's token (`hyn_`); an Account's credential |
| **Box** | The bubblewrap sandbox one pi process runs in (issue #260): its own processes, its Bot's directory and its chat's sessions, the system read-only, the host's network. The word is OpenMausBot's ("bot box") | A Node, a container or a VM |
| **User** | Someone who signs in to the web client with a name and a password, made on the server; acts as the owner | An Account (a subscription a CLI or the gateway runs under); a Client token |
| **Web session** | A signed-in browser: a cookie whose secret the control plane keeps as a hash, good for 30 days after its last use | A CLI's session (`cli_session_ref`); a Conversation |
| **Model gateway** | The control plane module that serves models to pi, to workers that are not a vendor's CLI and to the owner's tools: an OpenAI-compatible API over the Model table. It picks the Account and records usage. A vendor's CLI (Claude Code, Codex) does not go through it | A Node's egress proxy |
| **Model table** | The models the Model gateway serves, declared by the owner: a public name, what it can do (chat, images, speech), and its targets (provider and upstream model) in fallback order. A model that is not in it is refused | A provider's own model list |
| **Gateway key** | A bearer key for the Model gateway: one for the coordinator, one per tool or machine of the owner, one per Dispatch of a worker that uses the gateway (revoked when it ends), each with the models it may use | A Client token; an Account's credential |
| **Search provider** | A service that answers a web search for every agent through the control plane (issue #354): Exa (with a key or through its public MCP), Parallel (its public MCP), the owner's SearXNG, or the own web search of a Codex, Claude or Antigravity account the owner logged in, tried in turn; one that answered 429 rests for a while. A page is read by the control plane itself, with Jina Reader as its fallback. The word is OmniRoute's | A Provider, which serves models; a Connection or an Integration, which acts as the owner's account |
| **Git host** | Where a repository lives and its pull requests are opened: `github.com`, `gitlab.com`, or a company's server the owner declared, each of a kind (`github`, `gitlab`). A request to merge is a pull request on every host | A Node, which is a machine that runs Workers |
| **Transcript** | What a Worker said and did during one Dispatch, kept by the control plane as items in order: messages, reasoning, tool calls, their results and notices. The Node sends it from the Worker's journal | A Conversation, which is the CLI's own record on the Node; a Session |
| **Secret** | A named value kept by the vault, encrypted: an API key or a subscription's token set. It has versions; another record names it as `vault:<name>`. Its value is never shown | An Account, which uses a Secret; a Client token or Gateway key, which are stored as hashes |
| **Integration** | A service Hypomnema works with on the owner's behalf: a git host (named by its host), connected with a token, a service that signs in with an account, of which Google is the first (issue #103), a service Hypomnema works with as an app of the owner's, as Lark (issue #135), or a self-hosted service at an address of its own that an account signs in to with a user name and a password, as Superset (issue #203), or a cloud whose roles Hypomnema assumes with one key, as AWS (issue #331) | A connector, a plugin, an app |
| **Connection** | One account of an Integration that the owner authorized, under a label he chose (`work`); for an Integration that is an app, the app itself; for a self-hosted one, the account with the service's address; for AWS, one role. Its credential is a vault secret. An agent uses it only when a Run was given it or the owner allowed it for chats. A git host's single token of before 2026-11-10 is its Connection `default` | An account (that is a runtime's subscription), a login; the heading Connections of the Settings menu, which also holds Channels and the Vault (OpenClaw's and t3code's name for that group) |
| **Session** | A Dispatch's own keys (its Gateway key and agent API key), revoked when it ends. Called a vault credential session behind a node's proxy until 2026-11-13 | A CLI session or a chat; call those Conversation |
| **Announce** | A Worker's final report to the Coordinator, with outcome and evidence | A chat message to the owner |
| **Policy** | A rule that answers a tool call or request with ALLOW, DENY or ASK | A Gate |
| **Approval** | The owner's answer to one request to a service that a Policy answered ASK: approve once, approve for the rest of the Run or the chat, approve always for the Routine whose run asked (until the Routine's prompt, script or schedule changes), or reject. It shows the request decoded, and stays open until answered (issue #154) | A Gate, which a Task waits on; a permission prompt of a runtime's own |
| **Action** | One thing an agent can do with a service, as the owner names it (send mail, share a file): the requests that are it, and the answer it has for a Connection, which is allow, ask or never | A tool call; an API endpoint |
| **Epoch** | A counter on a Dispatch; a write from a stale epoch is refused | A timestamp |
