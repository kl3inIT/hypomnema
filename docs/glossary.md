# Glossary

One meaning per term. Use these words in code, documents, issues and messages. A term from a reference project that
means something else is named here once and not used.

| Term | Meaning | Not to be confused with |
|---|---|---|
| **Owner** | The one person who assigns work, approves gates and owns every resource | A user of a multi-tenant product |
| **Run** | One objective from the owner, such as "add login with Google to second-bite". Holds Tasks | A model "run" or a CI run |
| **Task** | One unit of work inside a Run, with dependencies on other Tasks of the same Run (a DAG) | Orca's task, which has the same meaning |
| **Dispatch** | One attempt to carry out a Task: placed on one Node with one Runtime, with an epoch for fencing. A retry is a new Dispatch | The Task itself; a Task may have many Dispatches |
| **Gate** | A decision a Task waits on, answered by the owner (plan approval, a question), or replaced by a Follow-up | A per-tool-call permission prompt, which is a Policy verdict |
| **Follow-up** | More work asked of a succeeded Task, or of one blocked at a Gate, which it replaces, as a note sent to its Worker, which continues its own Conversation, branch and pull request | A new Task; a reopen, which restarts a failed Task |
| **Auto-merge** | The git host's own merge of a pull request once its required checks pass and it has no conflict, turned on by the Worker that opened it (`gh pr merge --auto`, `glab mr merge --auto-merge`) | A direct merge, which a Worker never does |
| **Coordinator** | The agent that plans a Run, creates its Tasks, answers or forwards its workers' questions and summarises results; it does not do the work itself, and the control plane holds the Run's state. It is a part in a Run: a Bot takes it, or the owner's own agent (Claude Code, Codex) calling the Client API; each Run has one, recorded by its token. Until 2026-11-11 the glossary said "it is pi on the server" and that it holds no state; a Bot has a memory. Called Brain until 2026-11-07, as in older research notes; the role is Orca's coordinator | A worker |
| **Setup change** | A change of a Bot or a worker Profile that the Bot `coordinator` made from a chat: made, changed or removed, applied at once, shown as a card in that chat with Undo while nothing changed or used it since. After OpenMausBot's team setup receipt (issue #169) | A Routine's change by a Bot, which the Routine itself records |
| **Bot** | A long-lived agent of the control plane: an id that never changes, a name that is shown and may change (issue #466), a model, a persona the owner writes and a memory it keeps across chats. It talks with people in Chats, on the web or through a Channel, gives work to workers and may do work itself. It runs pi on the server. The **main Bot** is the one that is always there and alone changes the Bots: the Bot `coordinator`, known by that name until 2026-11-15 and by a fixed id since, whatever it is called; it was the Profile `coordinator` until 2026-11-11. The word is OpenMausBot's (owner, 2026-11-11) | A Worker, which carries out one Dispatch on a node and ends; a Profile, which is a worker's recipe; a Channel, which Lark calls a bot |
| **Routine** | Work a Bot does on a schedule, every N minutes or by a cron expression with its time zone: a prompt the Bot works on with its model in a new Chat each run, or a script, a file in the Bot's directory, that runs with the Bot's tools and no model. A prompt Routine may have a script too, which runs first and wakes the Bot only when it finds work (issue #656). The owner makes one, or a Bot does from its chat; it is on at once, and a Bot's change can be undone. Each run leaves a record. The word is OpenMausBot's (issue #211) | A Run, which is one objective from the owner and holds Tasks; a Task; a connector that syncs data, which is not built |
| **Channel** | A door to a Bot from a messaging service: an account at that service, of one kind (Lark today, a Lark app), and who may talk through it. A person's message there is a message of a Chat with the Bot. Every kind keeps its Channels in the same tables, `channels` with its `kind` and `channel_*` (issue #404) | The Bot behind it; an Integration, through which agents use a service |
| **Chat** | A conversation with a Bot, kept by the control plane; a Run the Bot creates belongs to its chat, which its events wake | pi's own session file, which pi resumes from, not the record; the Bot's memory, which is the same in all its chats |
| **Artifact** | What a Bot hands the owner to look at in its chat: an HTML page or folder (a dashboard, a diagram), a PDF, an image or any other file, shown with the `show_artifact` tool (by a Bot or a worker, in the chat of its Run) or `hypomnema artifact show`. It is a card in the chat that opens beside it, over the screen or on its own page, and keeps its revisions; showing it again by its id makes the next one. The word is Claude's, AI Elements' and assistant-ui's (owner, 2026-11-14); OpenMausBot says page, OpenClaw widget, ChatGPT canvas | A file attached to an owner's message, which stays in the Bot's folder; a file a Bot sends with `MEDIA:` (a file in Lark, a download in the web chat) |
| **Take** | What an agent filmed of the node's phone with `video_start`, `video_say` and `video_stop` (issue #817): one or more Segments placed one after another on one timeline, and the Steps it said, each at its time on that timeline, with where the owner's takeover paused it. Its `take.json` holds it, on the node while it is filmed and uploaded, then on the control plane, which keeps it until the owner deletes it. The word is autodemo's (a "take" of its camera) | The finished demo video made from a take (issue #818); a Transcript |
| **Segment** | One file of a Take: an MP4 of one stretch filmed with one configuration of the phone's encoder. A new one starts at the take's start, after the owner hands the phone back, when the phone turns or its encoder is reset, and when the stream starts again; it starts on a key frame and its last frame lasts until it ends. Written as fragmented MP4 while filmed and muxed into a regular MP4 as it closes | A fragment of an fMP4 file; a Chunk of an upload |
| **Step** | One line an agent said with `video_say` right before an action, at the take's time it arrived, with where it was about to tap and, perhaps, a new chapter | A Task, or a Dispatch's progress |
| **Orchestration** | The control plane module that keeps Runs, Tasks, Dispatches, Gates, leases, mailboxes and the event log, and is the only writer of that state. It runs nothing itself. Called execution until 2026-11-07; the name is Orca's (`src/main/runtime/orchestration/`) | The Coordinator, which decides; orchestration keeps the record |
| **Worker** | A CLI agent process (Claude Code, Codex, omp, opencode) carrying out one Dispatch | The Node it runs on; a Bot, which runs on the server and lives on |
| **Conversation** | A Worker's CLI conversation (a Claude Code session id, a Codex thread id) on one Node and worktree, recorded by orchestration. A later Dispatch of the same Task continues it when the previous Dispatch settled cleanly; a crash or an unknown outcome starts a new one with a recovery note | A Dispatch, which is one attempt and ends; a vault Session |
| **Runtime** | The kind of worker and how it is driven: `claude`, `codex`, `omp`, `opencode` | A model or a provider; pi, which a Bot runs on the server |
| **Skill** | A folder in the Agent Skills format (a `SKILL.md` with a name and a description, and files beside it) that an agent's CLI reads by itself when its work needs it. The owner adds one to the control plane, which keeps it in versions known by a digest of their files (called revisions in the API, the CLI and the code, whose names stay; the web says version, as for a Profile and a Secret: owner, 2026-11-12); a built-in skill ships compiled into the binaries | A tool, which an agent calls; a Profile's instruction, which is always in the prompt |
| **Profile** | A named, versioned choice of runtime, provider, model, effort and instruction that a worker runs with, through its Task. pi on the server ran as the Profile `coordinator` until 2026-11-11 and is a Bot since. A change is a new version; a Dispatch records the version it ran with. Called Role until 2026-11-09, when roles were defaults read from the environment. Named `<role>` for a role's default worker (`implementer`, `reviewer`, `explorer`) and `<role>-<vendor>` for another vendor's worker of that role (`implementer-codex`, `reviewer-claude`); a worker for one Bot's job is named for the job (owner, 2026-11-18, issue #835; `codex-worker` was `implementer-codex`'s name until then) | A Runtime, which is code on the node; the owner's own agent, whose model the owner picks |
| **Memory** | What an agent keeps across its work: a Bot's across its chats, an agent's (a Profile's) across the Tasks of all its workers, and the memory about the owner that every worker and Bot gets. The agent sees it as the directory `/memories`: `MEMORY.md`, entries one per line and always given; `USER.md`, the memory about the owner; and **notes**, other files read only when needed (issue #589). Kept by the control plane (owner, 2026-11-13: MemoryOS until then) | A Transcript, which is what one Worker said and did; a machine's memory (RAM) on the Machines page; a CLI's own memory, which is off for workers |
| **Node** | A machine paired with the control plane that runs Workers: a VM, a server, a sandbox | Omnara's "machine", same meaning |
| **Free capacity** | How much room a Node has for one more Worker, the score a new Conversation is placed by: the mean of its free share by Requests against its Allocatable, of its measured CPU and of its measured memory, as Kubernetes' LeastAllocated scores a node (issue #731). A Node with under 1 GiB of memory available is low on memory and takes no new Conversation; a Task with only such Nodes waits with the reason `nodes_low_memory` | Allocatable, which only refuses; a Node's cap |
| **Allocatable** | What the Dispatches of a Node may ask for in all: its CPUs and memory, as its hello says them, less what the owner reserved, and its memory less 1 GiB more; never below 0 (issue #731, as the kubelet's allocatable). A Node takes a Dispatch while the Requests of what it runs, plus this one, fit it in CPU and memory both | Free capacity, which orders; measured use, which never refuses |
| **Request** | What a Worker asks of a Node, in CPU (millicores) and memory: its profile's `requests`, else 1 core and 3 GiB for building work; copied onto the Dispatch when it is made (issue #731, as a Kubernetes container's requests) | Measured use, in a Node's stats |
| **Cap** | A Node's optional `max_dispatches`: the most Dispatches it runs at once besides what fits its Allocatable; none by default (issue #731, as Nomad's `node_max_allocs`). Called the node's limit until 2026-11-17, when it was required | A Guaranteed share |
| **Guaranteed share** | How many Dispatches a Bot (or the owner's Runs without a Bot) has a first claim on, `guaranteed_dispatches`, 4 by default: when room frees, the Bot furthest below its share goes first; a Bot may borrow any free room beyond it, and nothing running is stopped for it (issue #731, as Kueue's `nominalQuota`). Called the Bot limit, `max_dispatches`, until 2026-11-17, when it was a cap | A Cap, which refuses |
| **Account** | One credential for a model provider: a Claude, Codex or Antigravity subscription, an OpenCode Go key, an API key, or a Muse account's cookie jar (the Muse pool's). Kept by the control plane; a Runtime runs under it directly, the Model gateway serves it, or both; a Dispatch records which one it used | A user account of the owner |
| **Client API** | The control plane's one API, `/api/v1`, described by `api/openapi.yaml`, which the web client calls with a Web session, and the `hypomnema` CLI and coordinators with a Client token | The node API (nodes only); the Model gateway |
| **Client token** | A bearer token for the Client API, of kind `owner` (everything) or `coordinator` (its own Runs, and reading the rest); shown once, stored as a hash. A `bot` token is one pi process's own: what its coordinator token does, in its chat and as its Bot only, made when that pi starts and ended with it (issue #260) | A node's token (`hyn_`); an Account's credential |
| **Box** | The bubblewrap sandbox one pi process runs in (issue #260): its own processes, its Bot's directory and its chat's sessions, the system read-only, the host's network. The word is OpenMausBot's ("bot box") | A Node, a container or a VM |
| **Documents environment** | The one Python environment, built by uv under the coordinator's tools with pinned packages, whose `python` every Bot's box, and every Routine's script's (issue #507), finds first on its `PATH`, for the document skills (issue #401). A rebuild is a new generation; a running pi keeps the one it started with. The name and the design are Hermes's ("its shared, pinned documents environment") | A Bot's own virtual environment; the system's Python |
| **User** | Someone who signs in to the web client with a name and a password, made on the server; acts as the owner | An Account (a subscription a CLI or the gateway runs under); a Client token |
| **Web session** | A signed-in browser: a cookie whose secret the control plane keeps as a hash, good for 30 days after its last use | A CLI's session (`cli_session_ref`); a Conversation |
| **Model gateway** | The control plane module that serves models to pi, to workers that are not a vendor's CLI and to the owner's tools: an OpenAI-compatible API over the Model table. It picks the Account and records usage. A vendor's CLI (Claude Code, Codex) does not go through it | A Node's egress proxy |
| **Model table** | The models the Model gateway serves, declared by the owner: a public name, what it can do (chat, images, speech), and its targets (provider and upstream model) in fallback order. A model that is not in it is refused | A provider's own model list |
| **Time to first token** | For a streamed answer of the Model gateway, the time from the gateway receiving the request to the first chunk of the answer it wrote to the client, `ttft_ms` (issue #856, as LiteLLM's and Helicone's); none for an answer that is not a stream. Output tokens a second count only the time after it | The whole call's duration, `duration_ms`; the time the provider took to answer the gateway |
| **Repeated failure** | An escalation, `repeated_failure`, raised when a Task's Dispatch fails with the same failure class (and the same unknown cause) as its previous failed Dispatch, naming the class, the count and the Dispatches (issue #856, after OpenClaw's and Hermes's). It tells the Coordinator and the owner; the Task is retried as before | The breaker, which fails a Task after three counted failures whatever their reasons; a Worker's loop, stopped by the loop guard |
| **Gateway key** | A bearer key for the Model gateway: one for the coordinator, one per tool or machine of the owner, one per Dispatch of a worker that uses the gateway (revoked when it ends), each with the models it may use | A Client token; an Account's credential |
| **Tool family** | A group of Hypomnema's tools switched as one by its pattern (`web_*`, `audio_*`, `agent_browser_*`), with a line that says when to use it (`WhenToUse`, `agenttool.ToolFamilies`) | A CLI's own tools, which are not switched |
| **Tools block** | The `## Tools` section of a worker's rules and a Bot's prompt: a line for each Tool family the agent has whose line is set, built from its tools alone, the same for a worker and a Bot with the same families (issue #723) | A tool's own description, which travels with the tool |
| **Usage unit** | What a Gateway usage row counts besides tokens, each kind in its own: a web search, a page read, a second heard, a character spoken, an image (issue #723); priced by the unit from LiteLLM's price map | A token, which models count |
| **Search provider** | A service that answers a web search for every agent through the control plane (issue #354): Exa, Firecrawl, Parallel, Tavily or TinyFish with the owner's keys (several a provider, issue #393), Exa, Parallel, Firecrawl, Tavily or You.com without a key, or the own web search of a Codex, Claude or Antigravity account the owner logged in, tried in turn, the order shown, the keyed ones reordered and each one switched on or off on Settings → Gateway → Web search; a key or provider that was rate limited, refused or out of credits rests for a while. Only providers free without a card are integrated (owner, 2026-11-14). A page is read by the control plane itself, with Jina Reader as its fallback. The word is OmniRoute's | A Provider, which serves models; a Connection or an Integration, which acts as the owner's account |
| **Image provider** | A subscription that makes and edits images for every agent through the control plane (issue #431): the owner's Codex accounts (on a paid ChatGPT plan) or Antigravity accounts, asked in the order the owner set on Settings → Gateway → Images, each with the model the request names or the one set for it; an account's image model rests after a limit until the vendor's reset | A Search provider; a Provider, which serves chat models |
| **Muse pool** | The owner's Muse accounts (Meta's research agent at muse.ai), each a gateway Account of runtime `muse` whose credential is its muse.ai cookie jar, which agents ask through `muse_ask` (issue #782). A new thread takes the first account in the owner's order that is signed in and not resting; a thread stays with its account; an account out of quota rests until Muse's Settings → Usage shows room. Each account is asked in a browser context of its own in the shared browser's Chrome | An Integration's Connection, which a Bot is given to act as the owner; the shared browser's profile, which agents use |
| **OpenCode Go** | OpenCode's $10-a-month subscription for open models (GLM, Kimi, DeepSeek, Qwen, MiniMax, ...), a built-in Provider of kind `opencode_go` the Model gateway serves as `opencode-go/<model>` (issue #854). Each Console API key the owner pastes is an Account of runtime `opencode_go`; the keys rotate as a subscription's accounts do, and each model is called on the wire Go's model list names for it. OpenCode Zen, the pay-as-you-go service at another address, is not it | OpenCode, the coding agent (runtime `opencode`) |
| **Git host** | Where a repository lives and its pull requests are opened: `github.com`, `gitlab.com`, or a company's server the owner declared, each of a kind (`github`, `gitlab`). A request to merge is a pull request on every host | A Node, which is a machine that runs Workers |
| **Transcript** | What a Worker said and did during one Dispatch, kept by the control plane as items in order: messages, reasoning, tool calls, their results and notices. The Node sends it from the Worker's journal | A Conversation, which is the CLI's own record on the Node; a Session |
| **Secret** | A named value kept by the vault, encrypted: an API key or a subscription's token set. It has versions; another record names it as `vault:<name>`. Its value is never shown | An Account, which uses a Secret; a Client token or Gateway key, which are stored as hashes |
| **Integration** | A service Hypomnema works with on the owner's behalf: a git host (named by its host), connected with a token, a service that signs in with an account, of which Google is the first (issue #103), a service Hypomnema works with as an app of the owner's, as Lark (issue #135), or a self-hosted service at an address of its own that an account signs in to with a user name and a password, as Superset (issue #203), or a cloud whose roles Hypomnema assumes with one key, as AWS (issue #331), or the owner's own messaging account **linked as a device** of his by a QR code his phone scans, as WhatsApp (issue #615), whose session the control plane holds | A connector, a plugin, an app |
| **Connection** | One account of an Integration that the owner authorized, under a label he chose (`work`); for an Integration that is an app, the app itself; for a self-hosted one, the account with the service's address; for AWS, one role; for an account linked as a device (WhatsApp), the owner's number; a **user Connection** is the owner signed in as himself through one of an app Integration's apps (Lark's `me`, issue #468), used only by his own token and a Bot given it, on his own turn (only the main Bot until 2026-11-16, issue #618). Its credential is a vault secret. An agent uses it only when a Run was given it or the owner allowed it for chats. A git host's single token of before 2026-11-10 is its Connection `default` | An account (that is a runtime's subscription), a login; the heading Connections of the Settings menu, which also holds Channels and the Vault (OpenClaw's and t3code's name for that group) |
| **Session** | A Dispatch's own keys (its Gateway key and agent API key), revoked when it ends. Called a vault credential session behind a node's proxy until 2026-11-13 | A CLI session or a chat; call those Conversation |
| **Announce** | A Worker's final report to the Coordinator, with outcome and evidence | A chat message to the owner |
| **Policy** | A rule that answers a tool call or request with ALLOW, DENY or ASK | A Gate |
| **Approval** | The owner's answer to one request to a service that a Policy answered ASK: approve once, approve for the rest of the Run or the chat, approve always for the Routine whose run asked (until the Routine's prompt, script or schedule changes), or reject. It shows the request decoded, and stays open until answered (issue #154) | A Gate, which a Task waits on; a permission prompt of a runtime's own |
| **Action** | One thing an agent can do with a service, as the owner names it (send mail, share a file): the requests that are it, and the answer it has for a Connection, which is allow, ask or never | A tool call; an API endpoint |
| **Epoch** | A counter on a Dispatch; a write from a stale epoch is refused | A timestamp |
